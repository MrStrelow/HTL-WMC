# Seitenzonen: header, nav, aside, main, footer

## 1. Warum Zonen?

In [L01.1](L01.1-HTML-Ueberblick.md) haben wir Überschriften, Absätze, Listen und eine Tabelle einfach untereinander geschrieben. Für den Browser ist das eine lange Liste von Blöcken – er weiß nicht, **was davon der Hauptinhalt ist** und was nur Navigation oder Fußzeile.

Schau dir beliebige Webseiten an (eine Zeitung, Wikipedia, das Schulportal): Fast alle haben dieselben **Zonen**:

```text
┌───────────────────────────────────────────────┐
│ header   Logo / Titel        nav: Hauptmenü   │
├────────────┬──────────────────┬───────────────┤
│ aside      │ main             │ aside         │
│ nav:       │                  │               │
│ Seiten-    │ Hauptinhalt      │ Zusatzinfos   │
│ navigation │ (genau einmal)   │ Tipps, Links  │
├────────────┴──────────────────┴───────────────┤
│ footer   © Copyright, Impressum, Kontakt      │
└───────────────────────────────────────────────┘
```

**Unser Ziel ist ein klassisches 3-Spalten-Design**: links die Seitennavigation, in der Mitte der Hauptinhalt, rechts Zusatzinformationen, darüber der Kopf, darunter die Fußzeile. HTML5 hat für jede dieser Zonen einen eigenen, **semantischen** Tag.

---

## 2. Die Zonen im Einzelnen

In der Slide entsteht im Tab **„1 · Zonen aufbauen“** jede Zone in einem eigenen Schritt.

### `<header>` – Kopf der Seite
Der `<header>` ist der **einleitende Kopfbereich der gesamten Seite**: Name, Logo und die Hauptüberschrift `<h1>`.

### `<nav>` im `<header>` – Hauptnavigation
Die **Hauptnavigation** führt zu den großen Bereichen der Webseite (Home, Kapitel, Kontakt) und ist auf allen Seiten gleich. Deshalb steht sie **im** `<header>`. Inhaltlich ist eine Navigation eine **Liste von Links** – deshalb `<ul>`, `<li>` und `<a>`.

### `<aside>` mit `<nav>` – Seitennavigation (linke Spalte)
Die **Seitennavigation** gehört nur zum aktuellen Bereich (z. B. die Kapitel des Moduls) und ändert sich von Bereich zu Bereich.

**Warum steht sie in einem `<aside>`?** Ein `<aside>` kapselt Inhalt, der den Hauptinhalt **begleitet**, aber nicht selbst der Hauptinhalt ist. Genau das ist eine Seitenleiste. Darin steht wieder ein `<nav>` – eine Seite darf **mehrere** `<nav>`-Elemente haben.

| | Hauptnavigation | Seitennavigation |
| :--- | :--- | :--- |
| **Ort** | im `<header>` | im `<aside>` neben dem `<main>` |
| **Inhalt** | große Bereiche der Website | Unterkapitel des aktuellen Bereichs |
| **Ändert sich?** | nein, überall gleich | ja, je nach Bereich |

### `<main>` – Hauptinhalt (mittlere Spalte)
`<main>` umschließt den **einzigartigen** Inhalt dieser Seite. Alles, was auf jeder Seite gleich ist (Kopf, Navigation, Fußzeile), gehört **nicht** hinein. Es gibt **genau ein** `<main>` pro Seite. Die beiden `<aside>` stehen **neben** dem `<main>`, niemals darin.

### Zweites `<aside>` – Zusatzinfos (rechte Spalte)
Tipps, Downloads, weiterführende Links: Sie hängen nur **indirekt** mit dem Hauptinhalt zusammen. Damit wir die beiden `<aside>` unterscheiden können, bekommen sie eine `id` (`seiten-nav` und `zusatz-info`).

### `<footer>` – Fußzeile der Seite
Der `<footer>` schließt die **gesamte Seite** ab: Copyright, Impressum, Kontakt.

### Unsere Regel: genau ein `<header>` und ein `<footer>`
In unserer Welt gibt es **genau einen** `<header>` und **genau einen** `<footer>` – beide direkt im `<body>`. Wir verwenden sie **nicht** innerhalb von `<main>`, `<section>` oder `<article>`.

> **Für Interessierte:** Der HTML-Standard erlaubt `<header>` und `<footer>` auch innerhalb eines Beitrags. Das nutzen große Softwareprojekte, die ihre Seiten aus vielen **Komponenten** zusammenbauen. Warum wir das nicht machen, zeigt der optionale Tab **„⭐ header/footer in Komponenten“** in der Slide zu [L01.3](L01.3-Section-Article.html#optional/1).

## 3. Der fertige Code

```html
<body>
    <header>
        <h1>
            HTL Lernportal
        </h1>
        <nav id="haupt-nav">
            <ul>
                <li>
                    <a href="index.html">Home</a>
                </li>
                <li>
                    <a href="kapitel.html">Kapitel</a>
                </li>
                <li>
                    <a href="kontakt.html">Kontakt</a>
                </li>
            </ul>
        </nav>
    </header>

    <aside id="seiten-nav">
        <h2>
            Kapitel
        </h2>
        <nav>
            <ul>
                <li>
                    <a href="grundlagen.html">1. Grundlagen</a>
                </li>
                <li>
                    <a href="layout.html">2. Layout</a>
                </li>
                <li>
                    <a href="formulare.html">3. Formulare</a>
                </li>
            </ul>
        </nav>
    </aside>

    <main>
        <h2>
            Modul: HTML-Struktur
        </h2>
        <p>
            Der Hauptinhalt kommt genau <strong>einmal</strong> pro Seite vor. Lorem ipsum dolor sit amet.
        </p>
    </main>

    <aside id="zusatz-info">
        <h2>
            Tipps
        </h2>
        <p>
            Halte die <a href="https://developer.mozilla.org/de/">MDN Web Docs</a> offen.
        </p>
    </aside>

    <footer>
        <p>
            &copy; 2026 HTL Lernportal &bull; <a href="impressum.html">Impressum</a>
        </p>
    </footer>
</body>
```

## 4. Wo sind die drei Spalten?

Öffnest du den Code im Browser, steht **alles untereinander**. Das ist richtig so: Alle Zonen sind Block-Elemente, und Blöcke stapeln sich.

HTML beschreibt nur, **was** etwas ist. **Wie** es angeordnet wird, macht später CSS. In der Slide kannst du oben rechts auf **„HTML + CSS“** (Taste ``2``) umschalten: Mit **exakt demselben HTML** und etwas CSS (Grid) entsteht das 3-Spalten-Design. Zugeschaltete **„Komponenten“** (Taste ``4``) zeigen, welche Teile man später als eigene Bausteine programmieren würde. Beides ist nur ein **Ausblick** – CSS lernen wir später.

---

> **Wir merken uns:**
> 1. Fast jede Webseite besteht aus denselben Zonen: Kopf, Navigation, Hauptinhalt, Randspalten und Fußzeile. HTML5 hat dafür eigene semantische ``Block-Elemente``.
> 2. Der [``<header>``](../../../05_Glossar.md#header)-Tag bildet den einleitenden Kopfbereich der **gesamten Seite** (Titel, Logo, Hauptnavigation).
> 3. Der [``<nav>``](../../../05_Glossar.md#nav)-Tag kennzeichnet einen Navigationsblock, meist eine ``<ul>`` mit ``<li>`` und ``<a>``. Eine Seite darf mehrere ``<nav>`` haben: die **Hauptnavigation** im ``<header>`` (überall gleich) und die **Seitennavigation** im ``<aside>`` (je nach Bereich).
> 4. Der [``<aside>``](../../../05_Glossar.md#aside)-Tag kapselt Inhalte, die den Hauptinhalt begleiten, z. B. Seitennavigation oder Zusatzinfos. Er steht **neben** dem ``<main>``, niemals darin.
> 5. Der [``<main>``](../../../05_Glossar.md#main)-Tag umschließt den einzigartigen Hauptinhalt der Seite und kommt **genau einmal** pro Seite vor.
> 6. Der [``<footer>``](../../../05_Glossar.md#footer)-Tag schließt die **gesamte Seite** ab und enthält z. B. Copyright, Impressum oder Kontakt.
> 7. In unserer Welt gibt es genau **einen** ``<header>`` und **einen** ``<footer>`` – beide direkt im ``<body>``, nie in ``<main>``, ``<section>`` oder ``<article>``.
> 8. Im reinen HTML stehen alle Zonen untereinander. Erst ``CSS`` (z. B. Grid) ordnet sie als Spalten nebeneinander an – das HTML bleibt dabei unverändert.
