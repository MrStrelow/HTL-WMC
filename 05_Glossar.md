### Absatz
Ein zusammenhängender Textblock im Fließtext. In Markdown entsteht ein neuer Absatz zwingend dadurch, dass eine komplett leere Zeile im Quellcode gelassen wird. (Siehe auch *Paragraph*).

### Annotieren
Das Anreichern von reinem Text mit speziellen Symbolen oder Tags, um ihm eine Struktur oder Bedeutung zu geben (z.B. das Setzen einer Raute `#` vor einen Text, um ihn als Überschrift zu markieren).

### Ausführen
Das tatsächliche Starten und Laufenlassen eines Programms durch den Computer, nachdem es erfolgreich vom Compiler übersetzt wurde.

### Auszeichnungssprache
Eine maschinenlesbare Sprache (wie HTML oder Markdown), die rein dazu dient, Texte strukturell zu gliedern. Sie nutzt keine Klick-Menüs für das Design, sondern annotiert Text mit Symbolen, um festzulegen, ob es sich um eine Liste, eine Überschrift oder ein Zitat handelt.

### Blockzitate
Optisch abgegrenzte oder eingerückte Textblöcke, die verwendet werden, um Zitate, Warnhinweise oder besondere Notizen hervorzuheben. In Markdown werden sie durch ein Größer-als-Zeichen (`>`) am Zeilenanfang erzeugt.

### Bugs
Programmfehler. Oft handelt es sich dabei um logische (semantische) Fehler, bei denen das Programm zwar ohne Absturz läuft, aber ein falsches oder unerwartetes Ergebnis liefert.

### Code-Block
Ein eigenständiger, mehrzeiliger Bereich innerhalb eines Dokuments, der Programmcode darstellt. In Markdown wird ein Code-Block meist von drei Backticks (```) umschlossen. Im Gegensatz zu Inline-Elementen steht ein Code-Block optisch als abgetrennter Kasten auf der Seite.

### Compiler
Ein Übersetzungsprogramm, das von Menschen geschriebenen Quellcode (z.B. C#) streng und vollständig in maschinenlesbaren Code umwandelt. Wenn der Code auch nur den kleinsten Syntax-Fehler enthält, bricht der Compiler sofort mit einem Fehler ab.

### CSS
Steht für **C**ascading **S**tyle **S**heets (Kaskadierende Gestaltungsbögen). Es ist eine Formatierungssprache, die HTML ergänzt. Während HTML für den Inhalt zuständig ist, wird CSS verwendet, um das visuelle Aussehen (Design, Layout, Farben, Abstände, Schriftarten) der Webseite zu gestalten.

### Darstellung
Das finale, für den Menschen sichtbare optische Ergebnis. Sie entsteht ganz am Ende der Verarbeitungskette, wenn der Renderer aus der reinen Struktur (z.B. Markdown-Code) das grafische Layout berechnet hat.

### Datenstruktur
Eine bestimmte Art und Weise, Daten im Speicher des Computers zu organisieren, damit sie effizient verarbeitet werden können. Ein Parser wandelt rohen Text beispielsweise oft in eine strukturierte Baumstruktur um, mit der das Programm weiterarbeiten kann.

### Fehler
Ein kritischer Regelverstoß im Quellcode (meist syntaktisch). Er verhindert, dass ein Programm kompiliert oder ausgeführt werden kann, da der Computer die Anweisung schlichtweg nicht versteht.

### Grammatik
Das strikte Regelwerk einer Programmier- oder Auszeichnungssprache. Es definiert exakt, in welcher Reihenfolge Symbole, Befehle und Wörter kombiniert werden dürfen, um gültigen Code zu ergeben.

### HTML
Steht für **H**yper**t**ext **M**arkup **L**anguage (Hypertext-Auszeichnungssprache). Es ist die fundamentale Sprache des World Wide Web und wird verwendet, um das Grundgerüst und den Inhalt einer Webseite (wie Überschriften, Absätze, Bilder und Links) semantisch zu strukturieren.

### Inline
Bedeutet "in derselben Zeile" oder "im fließenden Text". Ein Inline-Element erzeugt keinen neuen Absatz oder Zeilenumbruch. Ein *Inline-Code* in Markdown hebt beispielsweise nur ein einzelnes Wort mitten im Satz als Code-Schriftart hervor.

### Kompilieren
Der technische Vorgang, bei dem lesbarer Quelltext durch einen Compiler in eine ausführbare Datei oder Zwischensprache übersetzt wird. 

### LaTeX
Eine sehr mächtige Textsatz-Sprache, die besonders im akademischen Umfeld genutzt wird, um wissenschaftliche Arbeiten und komplexe mathematische Formeln (wie Brüche, Wurzeln oder Matrizen) präzise und fehlerfrei darzustellen. 

### Linter
Ein Überprüfungs-Werkzeug, das Quellcode auf formale Mängel, Stilbrüche und unsaubere Formatierungen kontrolliert. Es zwingt Entwickler zur Einhaltung von Standards, ohne den Code selbst auszuführen.

### Markdown
Eine extrem simple und weit verbreitete Auszeichnungssprache, um Textdateien zu formatieren. Anstatt auf Menüs und Buttons (wie in Word) zu klicken, nutzt man einfache Textsymbole (wie `#` für Überschriften oder `**` für fetten Text). Wird in der Softwareentwicklung als Standard für Dokumentationen eingesetzt.

### Markdown-Code
Der rohe, unformatierte Text inklusive aller Symbole und Annotationen (wie `#`, `*`, `[]`), den man im Code-Editor tippt, bevor ein Renderer ihn in ein fertiges Layout verwandelt.

### Paragraph
Der englische Fachbegriff und HTML-Tag (`<p>`) für einen Text-Absatz. (Achtung: Dies ist ein *False Friend* und bedeutet in der IT nicht den Paragraphen aus einem Gesetzestext).

### Parsen
Der Vorgang, bei dem ein roher Text (Zeichenfolge) eingelesen, auf seine Grammatik hin analysiert und in eine logische Datenstruktur zerlegt wird.

### Parser
Das Programm oder die Komponente, die den Vorgang des Parsens übernimmt. Er fungiert als eine Art "Übersetzer", der reinen Text in ein Strukturmodell umwandelt, ohne jedoch bereits die Optik (Render-Schritt) zu generieren.

### Punkte
In unserem schulischen Kontext: Die Bewertungspunkte für abgegebene Zettelübungen oder Projekte. Werden formale Kriterien (wie Kommentare im Code oder sauberes Markdown) nicht eingehalten, können diese abgezogen werden.

### Renderer
Eine Softwarekomponente, die abstrakte Datenstrukturen (die oft vom Parser stammen) nimmt und daraus das finale grafische Layout berechnet und zeichnet (z.B. den Text fett macht oder Bilder anzeigt).

### Schema
Ein strenger, verbindlicher Bauplan für Daten. Es legt exakt fest, welche Form Daten haben müssen (z.B. "Ein Alter muss eine Zahl sein"), enthält aber im Gegensatz zu einem echten Programm keine eigene auszuführende Logik.

### Semantik
Die Bedeutung oder Logik hinter dem Code. Ein Satz kann syntaktisch richtig geschrieben sein, aber semantisch keinen Sinn ergeben (z.B. "Das grüne Auto schläft"). Ein semantischer Code-Fehler ist oft ein Logikfehler (Bug), der das Programm etwas Falsches berechnen lässt.

### Statische Analyse
Das Untersuchen von Quellcode durch Werkzeuge (wie Linter), indem der Code nur gelesen und auf Auffälligkeiten geprüft wird, ohne das Programm tatsächlich zu starten.

### Syntax
Die "Rechtschreibung" und Satzbau-Regeln einer Programmiersprache. Werden Klammern vergessen oder Befehle falsch geschrieben, entsteht ein Syntaxfehler, den der Parser oder Compiler sofort blockiert.

### Tabellen
Eine strukturierte Darstellung von Inhalten in Zeilen und Spalten. In Markdown werden sie visuell im Text mit senkrechten Strichen (`|`) für die Spalten und Bindestrichen (`-`) unter den Kopfzeilen gezeichnet.

### Warnings
Hinweise eines Compilers oder Linters. Sie bedeuten: "Dein Code funktioniert technisch und bricht nicht ab, aber er ist unsauber geschrieben oder könnte in bestimmten Situationen zu Problemen führen."

### WYSIWYG
Steht für "What You See Is What You Get". Ein Editor-Prinzip (wie in MS Word), bei dem der Text am Bildschirm während der Bearbeitung exakt so dargestellt wird, wie er später im Druck aussieht. Es vermischt Inhalt und Design direkt während der Eingabe.

### Attribut
Attribute stehen immer im öffnenden Start-Tag eines HTML-Elements. Sie bestehen aus einem Namen und einem Wert (in Anführungszeichen) und liefern dem Browser zusätzliche Informationen oder Eigenschaften für dieses Element (z. B. das Ziel eines Links mit `href="URL"`).

### Auszeichnungssprache
Eine maschinenlesbare Sprache (wie HTML), die zur Gliederung und Formatierung von Texten und Daten verwendet wird. Im Gegensatz zu einer Programmiersprache enthält sie keine Logik (wie Schleifen oder Bedingungen), sondern beschreibt lediglich Struktur und Bedeutung der Inhalte.

### Block-Element
Ein HTML-Element, das standardmäßig die gesamte zur Verfügung stehende Breite seines Elternelements einnimmt und vor sowie nach sich einen Zeilenumbruch erzeugt (z. B. `<div>`, `<h1>`, `<p>`). Block-Elemente bilden die grundlegenden "Bauklötze" des Seitenlayouts.

### Closing-Tag
Der schließende Teil eines HTML-Elements. Er sieht genauso aus wie der Start-Tag, besitzt jedoch einen Schrägstrich `/` direkt nach der öffnenden spitzen Klammer (z. B. `</p>`). Er markiert das Ende des Elements.

### CSS
Cascading Style Sheets. Eine Stylesheet-Sprache, die streng von der Struktur (HTML) getrennt wird und ausschließlich für das Design, Layout und die visuelle Darstellung der Webseite zuständig ist.

### HTML
Hypertext Markup Language. Die standardisierte Auszeichnungssprache des Webs. Sie ist dafür zuständig, die Struktur und Bedeutung von Inhalten auf einer Webseite zu definieren.

### HTML-Element
Die vollständige Einheit in HTML, bestehend aus dem Start-Tag, dem umschlossenen Inhalt und dem Closing-Tag (z. B. `<p>Das ist der Inhalt.</p>`).

### Inline-Element
Ein HTML-Element, das sich in den fließenden Text einreiht, ohne einen neuen Zeilenumbruch zu erzeugen. Es nimmt nur exakt so viel Breite ein, wie sein Inhalt benötigt (z. B. `<a>`, `<span>`, `<strong>`).

### Semantik
In HTML bedeutet Semantik (oder "Semantisches HTML"), dass Tags entsprechend ihrer inhaltlichen Bedeutung gewählt werden und nicht aufgrund ihres Aussehens. Beispielsweise wird `<h1>` gewählt, weil der Text inhaltlich die Hauptüberschrift ist, nicht weil der Text groß und fett aussehen soll. Dies ist essentiell für Suchmaschinen und Barrierefreiheit.

### Start-Tag
Der öffnende Teil eines HTML-Elements, geschrieben in spitzen Klammern (z. B. `<p>`). Er markiert den Beginn des Elements und kann zusätzlich Attribute enthalten.

### Tag
Ein Schlüsselwort (Markierung) im HTML-Quelltext, das in spitzen Klammern `< >` geschrieben wird. Tags weisen den Browser an, wie der umschlossene Text zu interpretieren ist.

### Inline-Element
HTML-Elemente, die keinen eigenen Absatz oder Zeilenumbruch im Dokument erzwingen, sondern sich direkt in den laufenden Textfluss einpassen. Sie nehmen horizontal nur so viel Platz ein, wie ihr tatsächlicher Inhalt (Text oder Grafik) benötigt. Typische Beispiele sind `<a>`, `<strong>`, `<em>` und `<img>`.

### Block-Element
HTML-Elemente, die ein eigenständiges rechteckiges Kästchen im Layout aufspannen. Sie beginnen stets auf einer neuen Zeile, dehnen sich standardmäßig über die gesamte verfügbare Breite ihres übergeordneten Eltern-Elements aus und erzeugen nach sich einen Zeilenumbruch. Typische Beispiele sind `<header>`, `<main>`, `<section>`, `<article>`, `<p>` und `<ul>`.

### Non-Closing Tag
HTML-Tags, die keinen schließenden End-Tag (`</...>`) besitzen, da sie per Definition keinen inneren Text oder weitere geschachtelte Tags umschließen können (*Void Elements*). Sie stehen als in sich geschlossene Anweisung im Code – beispielsweise `<img>` zum Einbinden einer Datei, `<br>` für einen manuellen Zeilenumbruch oder `<hr>` für eine thematische Trennlinie.

### Head
Der nicht-visuelle Kopfbereich eines HTML-Dokuments (`<head>`). Er enthält technische Metadaten, Konfigurationen wie Zeichenkodierung (`UTF-8`), den Fenstertitel (`<title>`) sowie Verknüpfungen zu externen Stylesheets (`<link rel="stylesheet">`). Die Inhalte im Head werden im Inhaltsbereich des Browserfensters niemals direkt gezeichnet.

### Body
Der Dokumentkörper (`<body>`) einer Webseite. Er fungiert als übergeordneter Container für alle sichtbaren Inhalte einer Seite, darunter Texte, Bilder, Tabellen, Navigationsleisten und Formulare. Alles, was Nutzer auf dem Bildschirm sehen oder womit sie interagieren können, muss zwingend innerhalb des Body deklariert werden.

### Main
Ein semantisches Struktur-Element (`<main>`), das den zentralen, thematischen Hauptinhalt des Dokuments umschließt. Es darf pro HTML-Seite nur ein einziges Mal verwendet werden und schließt wiederkehrende, seitenübergreifende Komponenten wie Hauptmenüs (`<header>`), Seitenleisten (`<aside>`) oder Fußzeilen (`<footer>`) explizit aus.

### Paragraph
Ein strukturelles Block-Element (`<p>`), das zur Auszeichnung von Fließtextabsätzen dient. Browser versehen Paragraphen automatisch mit einem standardmäßigen Außenabstand nach oben und unten, um Textblöcke visuell voneinander zu trennen. Fließtext innerhalb semantischer Container sollte niemals unstrukturiert stehen, sondern stets in Paragraphen gekapselt werden.

### Strong
Ein semantisches Inline-Element (`<strong>`), das Textabschnitten eine besondere Wichtigkeit, Ernsthaftigkeit oder Dringlichkeit verleiht. Im Gegensatz zu rein visueller Fettformatierung (früher `<b>`) teilt `<strong>` auch Assistenztechnologien wie Screenreadern mit, dass der Inhalt mit besonderem Nachdruck gelesen werden soll.

### Emphasis
Ein semantisches Inline-Element (`<em>`), das zur Betonung einzelner Wörter oder Phrasen innerhalb eines Satzes dient. Die Betonung verändert die klangliche und inhaltliche Bedeutung der Aussage. Screenreader heben Wörter in `<em>`-Tags stimmlich hervor; visuelle Browser stellen sie standardmäßig kursiv dar.

### Header
Ein semantischer Einleitungsbereich (`<header>`), der entweder am Anfang des gesamten HTML-Dokuments steht (und dort beispielsweise Logos, Webseitentitel und Hauptnavigation bündelt) oder als Einführungskopf innerhalb eigenständiger Inhaltsabschnitte wie einem `<article>` genutzt wird (z. B. für Überschrift, Autor und Veröffentlichungsdatum).

### Footer
Ein semantischer Abschlussbereich (`<footer>`), der Metadaten, Verfasserangaben, Urheberrechtshinweise oder thematisch untergeordnete Links bereithält. Ein Footer kann sowohl global am Seitenende platziert werden als auch lokal am Ende eines einzelnen Artikels oder Kapitels stehen.

### Aside
Ein semantisches Element (`<aside>`), das Randinhalte umschließt, die mit dem umgebenden Hauptinhalt nur am Rande zusammenhängen. Es dient typischerweise für Navigationsspalten (*Sidebars*), Glossar-Einschübe, weiterführende Linksammlungen oder Kontaktinformationen und kann vom Haupttext getrennt werden, ohne dessen Kernaussage zu zerstören.

### Nav
Ein semantischer Bereich (`<nav>`), der Navigationslinks bündelt. Er wird für primäre Menüleisten, Inhaltsverzeichnisse oder Seitennummerierungen (*Pagination*) eingesetzt, um Nutzern und Suchmaschinen die gezielte Erkennung zentraler Wegweiser durch die Webpräsenz zu erleichtern.

### Section
Ein generisches, thematisch abgegrenztes Gliederungselement (`<section>`). Es dient dazu, ein Gesamtdokument in sinnvolle Kapitel, Abschnitte oder Rubriken zu unterteilen. Eine Section besitzt typischerweise eine eigene Überschrift (`<h2>`–`<h6>`) und ist im Gegensatz zu einem `<article>` außerhalb des Dokumentkontexts meist nicht als eigenständiges Werk verständlich.

### Article
Ein modularer, in sich geschlossener Inhaltsblock (`<article>`), der ein eigenständiges Werk repräsentiert. Typische Beispiele sind News-Meldungen, Forenbeiträge, Kundenbewertungen oder Blogartikel. Kennzeichnend ist, dass ein `<article>` ohne Bedeutungsverlust aus der Webseite herausgelöst und auf anderen Plattformen oder RSS-Feeds wiederverwendet werden kann.

### Table
Eine HTML-Struktur (`<table>`) zur Darstellung zweidimensionaler relationaler Daten in Zeilen und Spalten. Sie besteht semantisch aus dem Tabellenkopf (`<thead>`) für Spaltentitel, dem Tabellenkörper (`<tbody>`) für Datensätze und optional dem Fuß (`<tfoot>`). Tabellenzeilen werden mit `<tr>` deklariert; Zellen werden über `<th>` (Kopfzelle) bzw. `<td>` (Datenzelle) befüllt. Tabellen dürfen nicht für Webseitenlayouts zweckentfremdet werden.

### Anchor
Ein interaktives Verknüpfungselement (`<a>`), das einen Hyperlink deklariert. Über das Pflichtattribut `href` referenziert der Anker entweder externe Webadressen (`https://...`), lokale Dateipfade (`ueber-uns.html`), interne Sprungmarken zu HTML-IDs auf derselben Seite (`#abschnitt2`) oder Systemprotokolle wie E-Mail (`mailto:`).

### Horizontal Rule
Ein strukturelles Trennelement (`<hr>`), das einen thematischen Themenwechsel oder Bruch auf Absatzebene anzeigt. Es besitzt kein End-Tag und wird von grafischen Browsern standardmäßig als dezente durchgezogene Querlinie über die gesamte Inhaltsbreite gezeichnet.
